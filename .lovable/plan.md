# Audit Report v3 — A4 PDF + editorial redesign

Goal: make the exported PDF a true A4 document, readable without zooming on phone, tablet and desktop, and make it look like a client-ready briefing instead of a dumped dashboard. No crawl, scoring, or issue-detection logic changes.

## 1. Real A4 output

- `@page { size: A4 portrait; margin: 16mm 14mm; }` so browsers lay the report out on A4 rather than the default Letter.
- Print root gets a fixed A4 content width (`180mm`) and a print type scale sized for A4 reading, not screen-shrunk: body 10pt, small labels 8pt, section titles 16pt, big numbers 22-28pt. Line height 1.45.
- First page becomes a proper cover band (masthead + score band), then numbered sections flow.
- Running footer line on each page: domain · crawl date · "Page X" via CSS counters where supported.
- Widow/orphan control: `orphans: 3; widows: 3`, headings keep with their content, table headers repeat, single cards/rows stay unsplit — long lists still flow across pages so we don't create blank pages.
- Colour printing: `print-color-adjust: exact` on the masthead and score bars so the design survives the PDF engine, with sensible ink-light fills.

## 2. Responsive on-screen report

The screen report adopts the same editorial layout (dark-theme version of the paper palette), and becomes genuinely mobile-friendly:

- Single column under 640px, two columns at tablet, the full 4-up score grid only on desktop.
- Minimum 14px body text on mobile (today's 10-11px utility sizes are the "have to zoom" problem), URLs wrap with `break-words`, tables switch to stacked label/value rows on narrow screens.
- Options bar (prepared-for, URL cap, section toggles, CSV buttons) stacks vertically on mobile and stays `no-print`.

## 3. Aesthetics — editorial briefing

Direction: cream paper + brand lime, Instrument Serif headlines with Work Sans body and a mono for labels/URLs. Structure borrowed from the reference, identity kept ours.

- **Masthead**: deep ink panel with a soft lime radial wash, eyebrow line ("Technical SEO Audit · Client Briefing"), serif site title, then a meta strip: Prepared for / Crawl date / Pages analysed / Prepared by.
- **Grade band**: conic-gradient health dial (score as the sweep) beside large Critical / Warning / Info counts.
- **Numbered sections**: `01 Executive Summary`, `02 Category Health Scores`, `03 Priority Remediation`, then response codes, indexability, duplicates, crawl depth, orphans, redirect chains, site structure, appendix — each with a mono section number in lime, serif title, one-line subtitle.
- **02 Category Health Scores** (the section you called out): replaces the current bar list with a hairline-gridded score card grid — mono category name, oversized serif score with `/100`, thin severity-tinted meter, and a plain-English issue line ("4 issues · 1 critical"). Last cell holds the scoring note.
- **03 Priority Remediation**: rank numeral in light serif, severity + category tags, serif issue title, mono scope line ("44% of the site · impact 63/100"), impact meter, then two columns "Why it matters" / "Recommended action".
- Data sections use hairline mini-tables with dot severity markers, callout strips for orphan/redirect counts, and chip-based hop flows for redirect chains.
- **Appendix note** at the end: dark panel titled "Full dataset & affected URLs" explaining that the complete per-issue URL list and raw crawl data live in the CSV exports, sized for the technical team. **No "Issues CSV Export →" link/button** — a PDF can't trigger an export, so the CTA is dropped entirely (CSV buttons stay in the on-screen options bar).
- Footer: domain, crawl date, "Generated by Sitemap Scout".
